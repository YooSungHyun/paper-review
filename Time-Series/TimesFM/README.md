### 1. Introduction

1. 요즘 시계열 딥러닝 모델들은 ARIMA같은 방법론보다 좋은 성능을 자주 나타내고 있음.
2. 와중에 LLM에서는 사전학습을 통해 제로샷같은 것도 됨
3. 시계열을 방대한 데이터로 학습하면 제로샷 되지 않을까? -> 근데 시계열은 문맥이랄게 없음. 그리고 시간 단위별 세분화된 예측기능도 필요
4. TimesFM을 제시한다. 예측 이력 길이, 예측 길이, 시간 세분화 수준이 달라도 잘 동작한다. 실제 데이터와 증강된 데이터를 활용한다. 그리고 디코더 스타일 아키텍쳐를 활용한다.
5. 사전학습이 실제로 가능하다는걸 증빙하며, 요즘나오는 GPT-3나 Llama-2를 활용해서 제로샷으로 하는 방법론보다 훨씬 적은 비용으로 훨씬 뛰어난 성능을 보인다.

사실 이게 중요한건 아니고, 1:1이냐 N:1이냐, N:N이냐 뭐 이런 개념으로 일단 이해해놓자.

### 3. Problem Definition

1부터 L까지 넣으면 L+1부터 L+H까지를 예측하는 모델을 쓰고, Loss Function은 MAE라는걸 쓴다. -> 아주 일반적인 시계열 모델의 Problem Definition이다.

콜센터에서 콜 예측을할때 MAE는 불합리하다는 생각을 해본적이 있다. 그 이유는 콜센터의 시계열은 시즌성을 가지기 때문에 (예를 들어, 소카의 콜은 휴가철에 제일 많이 들어온다.) 모든 기간별로 Weight를 1로 주는 MAE는 불합리하다고 생각했고, 새로운 Loss Function을 응용하여 좋은 성과를 낸 경험이 있다. (**MASE**: https://shyu0522.tistory.com/13)

### 4. Model Architecture

NLP는 여러 문장 길이에 따라 잘 학습됨을 보이지만, 시계열에 따라 몇가지 특화된 설계 선택지가 있다.

1. Patching
   ViT에서 나오는 그 Patch와 비슷하다고 보면된다. Vision Transformer에서는 이미지가 비트와 채널로 엄청 잘게 쪼개져있기 때문에, 바둑판같은 형태로 쪼개서 특정 부분만큼을 덩어리로 생각한다. 진짜 더 쉬운 해석으로는 막말로 RAG Chunk단위로 Next Chunk Prediction하는 모델을 만들면, Chunk가 Patch와 같은 맥락이라고 이해하면 된다.

2. Decoder-only model
   자세한 설명은 생략한다.

3. Longer output patches
   통상적으로 시계열에서는 Auto-Regressive는 위험한 것으로 표현된다. 왜냐면 오류가 계속 누적될 여지가 있으면서도 연속값이기 때문에 오차를 0으로 맞추는거 자체가 불가능하기에 노이즈가 필경 낄 수밖에 없기 때문이다. (텍스트처럼 같은 문맥인데 다른 표현같은 개념이 없음)
   따라서, 한번에 통으로 예측하는게 더 좋은 정확도를 보이지만, 문제는 제로샷 예측은 시계열이 정해진게 아니기 때문에 얼마나 예측해야될지 알 수 없다는 어려움이 있다.

   입력이 32고, 출력이 128인 경우, 64개의 시간지점으로부터 65~192까지, 96개의 시간으로부터 97부터 224까지 예측하도록 학습시킨다. 그 다음 256부터 다음 256을 예측해야한다면, 127개의 해당하는 257부터 384까지 예측하고, 256+출력된 내용으로 385부터 512까지 예측한다. 
   어느정도 자기회귀를 감안하지만, 범위를 크게크게 잡아서 최대한 헷지하려는 모습같다. 패치를 너무 크게잡으면 시간순 같은 짧은 범위를 예측하기 어렵다고한다. (당연한 얘기)

4. Patch Masking
   1부터 전체 길이까지 랜덤한 길이로 마스킹하는 전략을 사용하는 것 같다. U2++라고하는 En-Decoder 기반 실시간 Streaming STT 모델을 학습할때도 비슷한 전략을 취하는데, kv cache 길이를 다이나믹하게 랜덤 선택하게 해서 예측을 언제는 3초 음성만 봤다가, 언제는 5초 음성 봤다가, 언제는 전체음성을 다보고 이런식으로 학습을 시킨다음 inference할때 고정된 kv cache 길이를 제공하여 인퍼런스한다. (물론 음성의 길이가 끝은 달라질테니 여기서 dynamic chunk cache한게 효과를 보긴본다.) 이 녀석도 비슷한 컨셉으로 할 것으로 보인다.

![1](img/1.png)

- **Input Layers**
  Transformer 입력 토큰으로 전처리 하는 레이어.
  연속적이면서 **겹치지 않게** 분할한다음 residual block에 의해 model_dim 크기의 벡터로 처리된다.
  residual 이 있는 MLP블록으로 처리한다고한다. (왠지 lstm을 썼을거같은데 안써버리네...? 최대한 임베딩이랑 비슷한 느낌을 내려고 그런가...)
  패딩 마스크 m1도 제공된다고 한다. (마스크도 패치단위로 들고다니며, 패치 안에서 일부만 마스크될 수도 있다)
  포지셔널 인코딩이 붙는다.
- **Stacked Transformer**
  Transformer Decoder Layer. 자세한 설명은 생략한다.
- **Output Layers**
  patch가 32, output이 128이라고 가정하면
  patch1은 1~32까지 있고, 이걸 StackedTransformer를 지나면 o1이라고 볼 수 있다. LLM의 LM head는 이걸 vocab으로 투영하지만, 얘는 그렇게 안하고, output 회귀로 뱉으면 그만이니까 예를들어 512를 128로 그냥 바로 찍는다.
  그러면 [batch, o_n, 128] 로 나오고 o1,o2,o3이 각각 자기로부터 다음 128개에 대한 시계열 연속값을 찍는다고 보면 된다.
- **Loss Function**
  MSE를 사용한다. 추가적인 방법들도 있는데 헤드를 추가해서 quantile 값을 같이 맞추게 한다거나, 평균과 표준편차를 같이 예측하게 해서 NLL로 풀어내는 방법 등이 있다.
- **Training**
  Decoder 학습과 동일하나, 마스킹 부분이 핵심이다. 마스킹을 left padding 하듯이 하는데, p-1까지만 이루어지니까 위의 예처럼 patch가 32면 0~31까지. 즉 patch1안에서만 몇개를 마스킹할지 결정하게 된다.
  **왜 patch1만 마스킹하냐?**
  input의 종류가 예를들어 13개로 시작하는 경우가 있다면, 앞에 19개를 마스킹한 학습에서 13개를 볼 기회가 생긴다.
  만약에 50개를 넣고 인퍼런스하고싶다면? patch1에서 18개를 남기고 patch2에서 32개를 붙히는 형태로 50개를 이미 학습때 본 효과가 있다.
  시작만 고려하면되는게, rolling되듯이, 어느정도 겹치는 부분을 두고 inference되기 때문에, 다음 step에서는 기 출력된 값을 가지고 충분히 다음 시간 예측을 할 수 있기 때문에 patch1만 마스킹해도 많은 옵션의 길이 input을 처리 가능하게 된다는 것
- Inference
  심플한 방식인데, 예를들어 200번째 예측값을 알고싶다고하고, input이 30개밖에 없다면
  30개를 넣고 다음 128개를 예측하게하고, 30개에 128개를 붙혀서 다음 128개를 예측하게되면 200번째 값을 알 수 있게 된다.
  이는 이전 시계열이 auto regressive하게 attention에 쌓이니까 32개 패치로 학습했더라도 충분히 긴 길이를 어딘가에선 한번 학습하기 때문에 한번에 patch가 32여도 128개를 causal 하게 보게되는 효과가 있는 것이다.

### 5. Pretraining Details

Google Trends, Wikipedia Pageviews, 합성데이터를 활용한다.

합성데이터는 여러 시계열 패턴을 표현할 수 있는 모델 혹은 함수를 이용해서 만드는 모양이다. 자세한 설명은 Appendix. 8에 나와있다고 소개한다.

기타 데이터 소스로는 전력데이터, 교통데이터, 10분단위 기상데이터, 15분단위 트래픽 시계열 데이터 등등 거의 시계열 관련되서 구할 수 있는건 최대한 구해서 사용하는 모습이다.

데이터셋은 실제데이터 80%, 합성데이터 20%를 사용한다고 한다.(아마 데이터로더에서 하는 것일듯?)

시간별, 일별, 주간별 데이터에 동일한 가중치를 부여한다고 한다. (근데 주로 시간별보다 일별이 스케일이 더 큰데 이런건 그냥 했나봄...?;;;)

최대 512 컨텍스트 길이로 학습했다고 한다. 주단위는 이렇게 긴 데이터가 없어서 256으로 넣었다고 함. 월은 64

각 시계열 컨텍스트를 첫번째 입력패치의 컨텍스트 평균과 표준편차로 스케일링한다고 한다. (뒤에 스케일링 한다고 소개해놨군...)

### 6. Empirical Results

**Monash** Scaled MAE로 하는데, 제로샷은 뭐 역시 가장 좋다. 심지어 이건 해당 데이터셋을 타겟으로 학습한 것이 아닌데, 타겟으로 학습한거보다 잘된다고한다.

**Darts** ARIMA와 통계적으로 유의미한 차이는 없는 수준이었다. (ARIMA 클라스 씹....ㄷㄷ)
ARIMA가 잘 된 이유가 Darts는 단순시게열 예측문제고, seasonal ARIMA는 파라미터를 사람이 직접 바꿔가면서 바로바로 구해볼 수 있기 때문에 최적해를 구하기 쉽다고 표현함. (전통적인 시계열이 잘하는 문제도 딥러닝이 역시 잘하는 부분이다.)

**Informer/ETT** 4개의 데이터에 대한 512를 주고 96과 192 길이에 대해 예측하는 문제라서 4 task 2 horizon이라서 사실상 모델 8개가 필요할 수도 있는 케이스인데, 제일 잘한다고한다.

모델 사이즈가 200M까지 커지면 제로샷 에러가 줄어들었다고 한다.

horizon은 길수록 좋았다. 왜냐? Auto Regressive Step이 줄어드므로 오차 누적이 적어지니까.

input patch는 16 혹은 32가 제일 좋았다고 한다. 32로 길게잡으면 빵빵 뛰어나가니까 속도측면에서도 이득이 좋았다. (패치가 커질수록 선형적으로 빨라짐)

합성데이터는 좋았냐? -> 시간순은 데이터가 많아서 크게 의미 없었는데, 분, 연, 분기 등등 데이터가 별로 없는 케이스에서 개선이 보였다.

### Concluding & ETC

시계열도 사전학습을 통한 zero shot 성능을 강화할 수 있다.

시계열 데이터는 저작권 민감하니까 모델 만들어서 쓰던가 해라~

모델의 데이터에 따라 편향될 수 있어서, 모델러가 인지하지 못한 사이에 독일 범죄율 데이터가 들어간 모델을 한국 경찰청에서 쓰면 엉뚱한 결과를 초래할수도

=> 학습데이터 공개하고, 엥간하면 출처를 분명히 해서 써라~

200M으로 100B 길이 어치 데이터를 학습시키는데 16TPU로 2일 걸려서 LLM에 비하면 애기수준이긴한데, 한번돌리고 땡치는게 아니니까 생각보다 시계열 모델 학습시키는 비용보다는 크다.

LLM처럼 시계열 할루시네이션이 분명히 발생할 수 있으므로, Fine Tuining을 추가로 해서 할 것을 권장한다.

LLM은 프롬프트 튜닝이 가능한데, 얘는 사실 할 수 있는게 hyperparameter바꾸는 정도라 좀 애매하다. 뭔가 Input 시계열 데이터로 드리프트 하면 좋지 않을까?

그리고 시계열에서 중요한 피처중에 어떤 정량 혹은 비정량 condition이 중요할 수 있는데, 그런 부분들은 전혀 고려되지 않았다. (과거에 콜센터 했을땐 요일이나 날씨같은거 넣고 많이 했었음.)

물론 이걸 파운데이션 모델로 만드는데에 문제도 있다. 각 피처는 회사마다 사람마다 다를거라서, 제안하는 방식은 일단 output으로 1차 뽑고, condition으로 줘서 linear regression하는 방식을 제안한다.
